# Profession specialization reminders

Retail declares `C_ProfSpecs.GetNewSpecReminderProfName()` (one nilable `profName`) and `C_ProfSpecs.ShouldShowPointsReminder()` (one `showReminder` boolean) in `Blizzard_APIDocumentationGenerated/ProfessionSpecUIDocumentation.lua:142` and `:344`. The original consumer is `Blizzard_Tutorials/Blizzard_Tutorials_Professions.lua`. NewSpecChecker (lines 496–535) alerts `ProfessionMicroButton` with `PROFESSIONS_NEW_CHOICE_AVAILABLE_SPECIALIZATION` formatted with the name. SpecPointsChecker (lines 540–567) alerts with `PROFESSIONS_UNSPENT_SPEC_POINTS_REMINDER` when the points reminder is true and no name reminder applies.

Both queries visit candidates in this order: the first stored profession SkillLine, the second, then the first SkillLine of `Enum.Profession` 10 (Fishing) and 5 (Cooking). There is no name sort and no highest-points selection. A SkillLine is learned when its ID is positive, it is held, and both its current rank and its current-plus-bonus rank are nonzero.

Related SkillLines are the direct children whose `ParentSkillLineID` equals the line, ordered by signed `ParentTierIndex`, descending.

**Name reminder.** A candidate must be learned. It qualifies when its cached enabled flag is set and one of its tabs has `Enum.ProfessionsSpecTabState` exactly 2 (Unlockable); state 1 does not qualify. Otherwise each learned related SkillLine is tested the same way, recursively, even when the candidate's own enabled flag is clear. The first qualifying candidate with a SkillLine record selects its own name, not the related line's name. Selected empty text returns `""` and stops the search. No match returns one `nil`.

**Points reminder.** A candidate needs its cached enabled flag and points eligibility: an eligible unlock-kind-9/spend-kind-7 node on the candidate or on a related line. Only then is the currency read, starting again with the candidate's own tabs and then the related lines' tabs. A related line that is itself ineligible can supply the currency. Neither subscan applies the learned gate to related lines. The first TraitCurrency of type 1 that has a CurrencyTypes row is selected, in tab and `_Index` order. Its quantity is the current currency quantity, or zero when absent, divided by 100 when CurrencyTypes flag 8 is set. A quantity of at least 5 returns true. A smaller quantity, or no currency, makes that candidate false, and later candidates are still tested. An ineligible candidate reads no currency. If no candidate succeeds, the result is false.

**Evidence:** Retail 12.1.5 build 70688 WM49 part A, corrected by the WM55 follow-ups (Q2–Q4): the candidate order, gates, state-2 test, recursion, own-name selection, eligibility-before-currency, currency selection, flag 8, the per-candidate low-quantity rule, the missing learned gate in the points subscans, and the related-line relation and its descending order are VERIFIED; the one-`nil`, `""` and boolean publication is EMULATED. These points are INFERRED: the `ParentSkillLineID` and `ParentTierIndex` column names; row order for equal tiers (the native tie order is UNKNOWN; in 70391 no tie group has more than one line with tabs); a negative quantity also ends the candidate; the points subscans read only direct children. All tabs of one line share the same first point currency in 70391, so tab order cannot be observed there. No selected 70391 currency has flag 8; a unit test covers the division. `tools/gen_profession_spec_reminders.py` generates `crates/sim-data/data/profession_spec_reminders.rs`, with SkillLines in relation order, from SkillLine, SkillLineXTraitTree, TraitTreeXTraitCurrency, TraitCurrency and CurrencyTypes, build 12.1.5.70391. PTR and Forever reuse the Retail behavior without separate native evidence.

**Simulator inputs:** stored professions, base ranks and unlearned professions come from the professions model (`profession_data`, `crafting.unlearned_profession_ids`). Quantities come from `SimState.currency_info`. `SimState.profession_spec_inputs` supplies the rest, with empty defaults that return `nil` and `false`: related-line ranks, cached enabled flags, tab states and points eligibility. `C_ProfSpecs.GetStateForTab` publishes the same tab states ([tab state](profession-tab-state-favorite-orders.md)). **Known gaps (WM49):** the cache and configuration lifecycle, matching player configurations, shared trait purchase eligibility, conditions and costs, and node-rank arithmetic are not modeled; their results are supplied. Fishing and Cooking resolve only when the professions model lists them, because the Profession DB2 mapping is not loaded. Horde display names are not used.
