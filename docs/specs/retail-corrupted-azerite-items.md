# Mainline-family corrupted and Azerite items

Retail and PTR publish `C_Item.IsCorruptedItem(ItemInfo)` and `C_AzeriteItem.IsAzeriteItem(ItemLocation)`, as declared in `Blizzard_APIDocumentationGenerated/ItemDocumentation.lua:1195` and `AzeriteItemDocumentation.lua:77` in the pinned Retail UI cache. PTR declares the same signatures in `Blizzard_APIDocumentationGenerated/ItemDocumentation.lua:1232` and `AzeriteItemDocumentation.lua:77`. Both accept secret arguments only when the caller is untainted.

Corruption is supplied by item ID. Azerite identity is supplied by the existing active Azerite item location. An item not marked by supplied scenario state returns false; this is a simulator scenario default, not a claim about native item data.

The original Retail and PTR `SetItemButtonOverlay` and `AzeritePaperDollItemOverlayMixin:SetAzeriteItem` consumers must reflect distinct supplied values. Forever 70707 also publishes the existing supplied-location `C_AzeriteItem.IsAzeriteItem` query, declared in its `Blizzard_APIDocumentationGenerated/AzeriteItemDocumentation.lua:77-90` and consumed by `Blizzard_UIPanels_Game/Mainline/AzeritePaperDollItemOverlay.lua:13`. Its Camelot character-slot flow and original overlay must reflect distinct supplied locations. Forever also publishes the supplied item-ID overlay classifications declared in its `ItemDocumentation.lua:1232,1247,1262,1293,1611` and `SoulbindsDocumentation.lua:459`. Its original `Blizzard_ItemButton/Mainline/ItemButtonTemplate.lua:271` must show the corruption overlay for a marked item and not for an unmarked item, using the same scenario model. No native item classification defaults are inferred. Other profiles are outside this contract.
