# Keystone interaction

Retail 12.1.5 declares `C_Item.IsItemKeystoneByID(itemInfo)` in `Blizzard_APIDocumentationGenerated/ItemDocumentation.lua:1529–1542`, and `C_ChallengeMode.CanUseKeystoneInCurrentMap(itemLocation)`, `ClearKeystone()` and `CloseKeystoneFrame()` in `ChallengeModeInfoDocumentation.lua:11–31`. Blizzard's original item filter calls the two predicates at `Blizzard_FrameXMLUtil/ItemUtil.lua:141–145`; the keystone frame calls close and clear separately at `Blizzard_ChallengesUI/Mainline/Blizzard_ChallengesUI.lua:605–611`.

- Item classification uses the generated Item class and subclass: class 5, subclass 1 is a keystone; missing records are false. ItemInfo accepts a numeric ID, item link or known name; nil and unsupported types are errors.
- The map query requires a resolvable ItemLocation. Its first supplied modifier of kind 17 selects a generated MapChallengeMode record. It returns true exactly when the record's MapID equals the supplied current map selector; a missing record is false. An absent selector uses zero.
- Close clears only the receptacle GUID. Clear with no selected GUID leaves stale selection fields alone. Otherwise it removes lock reason 1 and clears the selection. If the aggregate lock changes and the item location resolves, the simulator emits `ITEM_LOCK_CHANGED` then `ITEM_UNLOCKED`; other lock reasons and the native lock flag remain intact. Bag and equipment lock queries expose the supplied aggregate lock state. Both commands return zero values.

**EMULATED inputs:** The host supplies location-keyed item modifiers, the current map selector, receptacle and selection state, and lock observations. Best-guess basis: Retail 12.1.5 build 70688 local WM32 A/B/C evidence; runtime transitions are not verified. **Known gaps:** modifier observations do not follow moved items automatically; action-usability cache changes and their event are not modeled; the CSV snapshot has no ItemSparse name rows for six of the 14 known keystone IDs, so those IDs classify numerically but cannot be resolved by name from this catalog. Full link grammar, server behavior and later event delivery remain unknown.
