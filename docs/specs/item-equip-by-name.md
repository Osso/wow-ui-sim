# EquipItemByName (Retail)

`C_Item.EquipItemByName(itemInfo, dstSlot?)` searches owned carried inventory before equipment. Selector 14 covers backpack, carried bags and reagent bag; selector 0 then covers those locations plus player root slots 0–29. Visit slots in increasing order, a bag before its contents, and select the first item-ID match. A later lock or eligibility refusal does not select another copy. Numeric IDs, item links and exact case-folded names resolve to the item ID. VERIFIED (WM57); name-table population remains UNKNOWN.

Without a destination, the selected item must have a player, a resolvable owner and location, native lock flag 2048 clear and lock-reason mask zero. Player equipment slots 0–18 are skipped. The pickup gate accepts enabled pickup control or UnitOnTaxi; UI initialization enables the control. Successful staging clears the previous cursor and installs mode 1 for the owned identity. When automatic processing proceeds, root source slots 19–34 and eligible class-6 items clear with restoration and no request. Otherwise a normal local request sets lock reason 1, emits `ITEM_LOCK_CHANGED` followed by `ITEM_LOCKED` on an effective unlocked-to-locked transition, and clears the cursor without removing that reason. Container event arguments are bag ID and one-based slot; equipment arguments are one-based inventory slot and nil. `C_Item.IsLocked` and `C_Container.GetContainerItemInfo().isLocked` report native flag 2048 or any lock reason. VERIFIED (WM44-B, WM57).

With an explicit numeric destination, subtract one and truncate; the result must be 0–18. A selected item already in that player destination is a no-op. The direct path does not stage or clear the cursor and does not apply the automatic class-6 or account-conversion branch. Preparation 1 stops, 2 defers and 0 or 3 proceed to confirmation. An actual decoded resident ItemSparse row gives status 0. VERIFIED (WM57).

A refundable owned item takes priority for equip confirmation. Otherwise Bonding 2 or a tradeable bound item, together with item/player eligibility, selects binding or tradeable confirmation. Effective binding depends on the owned bound marker, binding enchantment or species flag 16, not Bonding 1 alone. The native clock basis and the full eligibility rule remain UNKNOWN; tests may supply the predicate inputs. A selected confirmation retains item identity/source and leaves the staged cursor. VERIFIED tests, INFERRED state names (WM57).

The simulator records local requests and locks only. It does not synthesize a server equip response or alter equipment to claim success. Callback re-entry, exceptional paths, external completion and server results are UNKNOWN (WM44-B, WM57).
