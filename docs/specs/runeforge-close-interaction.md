# Runeforge interaction close

Retail, PTR and Forever declare `C_LegendaryCrafting.CloseRuneforgeInteraction()` in `Blizzard_APIDocumentationGenerated/LegendaryCraftingDocumentation.lua:11`. `Enum.PlayerInteractionType.LegendaryCrafting` is 48 (`PlayerInteractionManagerConstantsDocumentation.lua:61`). The original consumer `Blizzard_RuneforgeUI/Blizzard_RuneforgeFrame.lua` calls it from `OnHide` (line 99), and hides the panel on `RUNEFORGE_LEGENDARY_CRAFTING_CLOSED` (lines 114–115); `UIPanelWindows.RuneforgeFrame.showFailedFunc` references it (line 2).

The call reads no arguments and returns no values. It closes the current target only when the current interaction type is 48 and the target identity is nonempty. Otherwise no event fires and no state changes. When the runeforge close callback is installed, `RUNEFORGE_LEGENDARY_CRAFTING_CLOSED` fires first, with target state still intact. `PLAYER_INTERACTION_MANAGER_FRAME_HIDE` then fires with the interaction type current at dispatch. The close then clears the type, identity and installed callback. A close request is submitted whenever transport exists, including when no target closed.

Because state is not cleared before the closed event, a close that re-enters from Lua repeats the sequence before the outer close resumes. Through the original frame, the nested `OnHide` close fires the second closed event, hides with 48, resets and submits. The outer close then hides with 0 and submits again.
