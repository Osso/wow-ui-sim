# Retail currency filter and account data

Retail initializes the session filter to `DiscoveredOnly` (1). Filters 0 and 1 use the base list; filter 2 requires account currency data. Every accepted selection emits `CURRENCY_DISPLAY_UPDATE`, including repeated selections. The setter accepts numeric conversion and truncation to a signed 32-bit value, rejects nil and values outside 0–2, and converts non-convertible non-nil inputs to 0. It returns no values.

Readiness requires account and transaction loading to be clear and no pending character requests. It starts true. Selection 2 and `RequestCurrencyDataForAccountCharacters` use the same request logic. A disabled server input, absent context, or active account request suppresses it. Otherwise an invalidation input clears cached currency and transaction data; a nonempty currency cache suppresses the request, and an empty cache starts account loading. Server enable and context presence default to true as inferred scenario inputs. During loading, selection 2 retains the previous projection. A supplied account response clears account loading, installs supplied currency rows and emits `ACCOUNT_CHARACTER_CURRENCY_DATA_RECEIVED`. The other readiness blockers remain unchanged. When filter 2 is selected and ready, its rows are added to the base list. Other filters do not cancel requests.

Native evidence: WM60, Retail 12.1.5 build 70688, establishes the filter mapping, initial value, conversion hazard, events, and readiness predicate. Persistence is inferred as session-only. WM62 establishes the local request-start and suppression conditions. Initial server enable and context presence, server response timing, and live delivery ordering are unknown. Account rows and their currency information must be supplied by the host.
