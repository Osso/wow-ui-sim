**Scope:** read-only review of `[SIM_REPO]/build.rs`, `build/`, `.cargo/config.toml`, retained Spacer epoch records, and Cargo fingerprint text. No Cargo/build/check/test/process command, delegation, binary/library/archive content read, or hash operation was used. Fresh compile was not retried.

Fingerprints are configuration-specific and expose dependency/configuration tracking, but inspecting the available records does not establish a complete current “dirty versus fresh” explanation for each unit. No executable or library contents were inspected.

## Git/docs and test harness impact

- A Git/docs-only commit does not by itself make Cargo rebuild Rust crates. Cargo reacts to tracked source/build-script inputs, package/build configuration, dependency resolution, compiler/toolchain and feature/profile/target settings—not the commit identifier as such. A doc path explicitly declared as a build input could matter, but the reviewed `build.rs` declares no docs inputs.
- The owning command selects one integration-test target, `prefork_full_ui`. That test crate directly depends on `wow-ui-sim` and the test harness, so a changed relevant test source can dirty the owning test crate; a changed harness source can dirty its harness crate and dependent test target. The test path does not inherently compile every integration-test target just because Cargo has broad fingerprint records for the test tree.
- Profile/feature switching changes Cargo unit fingerprints and may require a separate compilation for units whose effective configuration differs. Shared dependencies can remain reusable when their effective unit configuration matches, but the records inspected do not prove exactly which units were fresh for these epochs. Switching profiles is therefore not a guaranteed way to avoid core-library/test-harness compilation.

## Actionable build-necessity assessment

For Git/docs-only edits, no core Rust rebuild is warranted by the build-script inputs reviewed; ordinary Cargo target selection/freshness remains the authority if a verification command is independently required. For Rust changes, relevant build-script/native inputs, lock/config/toolchain changes, or a different feature/profile unit, expect Cargo may need compilation. The retained Spacer evidence already supplies successful no-run compile results at `d5` Retail and `e8` PTR, while current `d151` owning Retail compilation is **incomplete** after host safety abort. Do not claim a clean current owning compile from the earlier producer epochs. If completion requires that exact owning compile, schedule a new attempt only under the existing host guard/authorization; this report does not authorize bypassing or relaxing it.

## Unsupported hypotheses

These source and records do **not** establish that compilation caused the observed memory pressure, that profile switching reduces peak memory, that Git/docs changes caused this compile, or that a particular crate/rustc process was responsible. They also do not establish whether a later retry would be incremental or fresh.
