## What the startup test really collects and asserts

`tests/startup_warnings.rs:39-94` creates a new environment, sets 1024×768 Game mode, installs the test handler, discovers Game startup Blizzard addons, and collects each load's diagnostics. It applies post-load workarounds, drains handler/runtime diagnostics, fires the headless test login/world-enter/post-login sequences, drains again, runs **one** `fire_on_update(0.016)` and drains once more. A direct OnUpdate failure becomes a warning. It is not a GUI soak, exhaustive load-on-demand walk, all-screen run, or ordinary CLI startup substitute.

`tests/startup_warnings/diagnostics.rs:1-100` retains three separate vectors. It merges load warnings, finalized nil observations, and missing requirements. Every load attempt drains the installed handler plus `env.drain_runtime_addon_diagnostics()`; direct load failures become `[load NAME] FAILED: ...`. A successful load also fires `ADDON_LOADED(NAME)`, records direct dispatch failure, and drains again. Runtime drainage takes the accumulated `runtime_addon_diagnostics` (`src/lua_api/env_runtime.rs:87-90`), not every possible printed message or every SimState field.

`tests/startup_warnings.rs:97-143` first checks a narrow AccountStore regression pattern, but finally asserts **the entire collected warnings vector is empty**; the AccountStore filter is not a warning allowlist. Nil observations and missing requirements are required only to have nonempty addon attribution. **Neither vector is asserted empty.** Their actual counts/content are not printed on success, so these artifacts cannot establish zero nil observations or zero missing requirements. Empty vectors would also satisfy attribution checks vacuously.

`tests/common/mod.rs:262-301` installs a handler inserting stringified messages plus optional debugstack into `__test_errors`; drainage clears and splits a separator-joined table. A missing/non-table collector returns empty, and Rust evaluation failure defaults to empty. No claim of an infallible collector follows from a passing assertion.

Discovery is filtered, not literally every Blizzard addon: `src/loader/mod.rs:507-509, 556-571, 735-770` uses screen-eligible parseable TOCs, excludes PTR-only/game-type-restricted TOCs, selects built-in non-LOD roots (subject to exclusions), and pulls required/implicit dependency addons before dependency ordering. Missing/unreadable discovery directories can yield an empty list; the test itself does not assert addon count. Nonetheless these runs are not zero *test* cases, and saved progress demonstrates substantial actual startup/workaround execution. C separately prints `Loading 283 Blizzard addons...`; that number must not be assigned to R/P without evidence.

Headless test startup is also intentionally narrower than normal Game startup: `src/startup.rs:218-241, 270-295` shows normal startup additionally closes special windows, fires `FIRST_FRAME_RENDERED`, unblocks splash alerts, and applies post-event workarounds. Headless test startup uses `fire_login_sequence(..., true)`, skipping the logged-in=true transition. Both paths explicitly skip `EDIT_MODE_LAYOUTS_UPDATED` (`src/startup.rs:466-484`). The test's single update is not the CLI's multi-tick/timer slice. Helpers can print and continue on errors (`src/startup.rs:113-125, 466-484, 557-562`); Lua helper pcalls can absorb errors. Therefore an empty warning vector is not a total census of all failures or all printed diagnostics.

Nil classification itself has limits: `src/loader/addon/nil_symbol_reports.rs:42-129, 179-201` summarizes accesses for the selected addon index, excludes qualifying globals later published non-nil by that addon in the matching environment, and deduplicates by environment/kind. Missing regular globals become observations; missing `C_*` globals become namespace requirements and missing members on `C_*` containers become method requirements. These are separate from warning health (`src/lua_api/state_types/runtime.rs:244-293`). Hooks observe accesses, not all absent APIs or unexecuted paths. These tests do not prove native API completeness or correctness.

## Ordinary PTR CLI: collector scope and suppression

C argv runs the saved `artifacts/wow-sim-normal` with `--no-addons --no-saved-vars lua-errors`, no `--exec-lua` probe. It uses 1600×1200 according to stderr, unlike the test fixture. `src/lua_errors.rs:27-84` suppresses fd 2 to `/dev/null` **during `collect_lua_error_startup`**, restores stderr and stdout, then prints final collected errors as pretty JSON plus LF and returns whether that list is empty. This ordinary invocation executes the screen-selected startup plus a bounded update/timer slice, not a full render/layout settle (`src/startup.rs:270-288`): initial timers, one tick, timers, two extra ticks with timer processing. Timer processing is bounded, not indefinite future coverage.

`src/lua_errors.rs:216-285` builds unique errors only from `state.lua_errors` whose normalized keys exist in `lua_error_counts`, preserving first-seen order and counts. Normalization uses the first line, removes the runtime-error prefix/location for dedup, while display preserves location/traceback (`:291-327`). Owner summary comes separately from `lua_error_records`. Empty JSON is not a collection of loader warnings, nil observations, missing requirements, stderr-only diagnostics, caught exceptions, or unvisited future errors.

Suppressed fd-2 output is not reconstructed from text logs. Errors reaching the canonical sink can remain in SimState and appear in final JSON even when their immediate prints were suppressed; arbitrary prints and startup-helper diagnostics do not thereby become collected errors. `src/lua_api/script_helpers.rs:532-551, 573-615` records error messages/owners/normalized counts and normally prints only a first normalized occurrence; recording itself can fail when app data is unavailable or SimState cannot be mutably borrowed. `src/lua_errors.rs:351-377` implements descriptor suppression/restoration. Therefore exact `[]\n` plus clean final summary does not certify an unsuppressed startup warning/error collector, even though R/P independently passed their narrower assertions.
