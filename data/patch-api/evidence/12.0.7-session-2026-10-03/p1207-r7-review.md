## 2. Authentication and mutation/dispatch order

`src/lua_api/frame/methods/secret_origin.rs:28–47` first gates on retail-12-0-7, then traverses `state.stack[state.base..state.top]`. ### Now — risks merging today

1. **Secret-origin UI functionality:** secret-number arithmetic unsupported even securely; secret token equality to ordinary literals false. Getters can break existing cached UI after accepted secret input/host origin. This is outside ordinary zero-origin history, but within the newly supported input space.
2. **Disclosure boundary:** accepted secret scroll produces plain callback argument, while getter is opaque. Retained behavior preserves public consumers but does not establish secret non-disclosure. Spec acknowledges this at `docs/specs/widget-secret-aspects-12-0-7.md:77`.
3. **Native policy unproved:** per-input public clearing, ignored extra/lock origin, Enable/Disable/Click clearing, historical cache epoch and protection/domain semantics are excluded, not fixed. INFERRED policies are tested as simulator choices, not authenticated against native.
4. **Font proof overstatement:** secure nonconstant update and authentication-specific error not demonstrated by the existing submatrix. All five validity rows remain correctly blocked; MessageFrame return mismatch persists.
5. **Acceptance limitations:** no fresh command execution, full cached startup, feature-off execution or broad suite proof. Public behavior is supported by exact source comparison and claimed narrow regression counts, not independent end-to-end runtime evidence. Extra Vec allocation on every gated setter call is unmeasured overhead.

### Final verdict

**ACCEPT WITH QUALIFICATIONS** for the explicitly bounded, partial-development artifact: real live state, wired producers, whole-call authentication and unchanged zero-origin ordinary contracts are present. **Not approval of native secret UI compatibility, whole-path non-disclosure, completed SetFont capability, or whole-row bounded coverage.** If merger's acceptance criterion is fully usable cached UI after any accepted secret input, this artifact does **not** meet it; the concrete arithmetic/token-comparison boundaries above must be resolved with native/consumer evidence, not vendor patches or shims.
